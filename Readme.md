# Проверка уведомлений Discord

Для локальных regression-тестов нужен установленный Gradle 9 с совместимой JDK:

```powershell
gradle test --tests DiscordNotifyTest
```

Полный набор: `gradle test`. Тесты вызывают `discordNotify` из `vars/unityCi.groovy` и проверяют JSON на границе HTTP, без отправки сообщений. Зависимость JUnit загружается из Maven Central при первом запуске.

В уведомлении каждый архив получает ссылку и размер файла из Jenkins. При превышении ограничений Discord оставшиеся архивы доступны по ссылке "All artifacts".

# Unity Accelerator

Если у ноды задана переменная окружения `UNITY_CACHE_SERVER` (`host:port`) или у job'а `options.cacheServer`, Unity запускается с кэшем импорта в Unity Accelerator: скачивает оттуда уже импортированные ассеты и досылает то, что импортировала сама. Холодная сборка на новой машине перестаёт импортировать проект с нуля. Пространство имён по умолчанию это папка job'а, переопределяется `options.cacheServerNamespace`. Без адреса сборка идёт как раньше.

# Установка Unity Editor и модулей

Для нод с Unity Hub 4 используется отдельный Unity CLI. Библиотека ищет его по `options.unityCliPath`, `UNITY_CLI_PATH`, в стандартном каталоге пользователя агента (`%LOCALAPPDATA%\Unity\bin\unity.exe` на Windows, `$HOME/.unity/bin/unity` на macOS), затем в `PATH`. На Windows кандидаты из `PATH` проверяются по метаданным исполняемого файла. Явный путь должен указывать на исполняемый файл CLI.

CLI подбирает версию редактора из проекта, при необходимости устанавливает её и добавляет модули для цели сборки. Если в списке для одной версии есть редакторы `arm64` и `x86_64`, модули ставятся для архитектуры выбранной записи. Для WebGL, iOS и Android проверяются каталоги модулей, для Android также SDK, NDK и OpenJDK.

Если CLI отсутствует, остаётся установка через старый Hub с путём `options.unityHubPath` или `UNITY_HUB_PATH`. Для установки в `Program Files` на Windows у агента должны быть права записи в этот каталог.

# Выбор ноды

Сборка идёт на ноду, выбранную по первому непустому из трёх:

1. параметр `NODE_LABEL` в форме "Собрать с параметрами";
2. `options.nodeLabel` в Jenkinsfile;
3. метка `unity`.

У каждой ноды в Jenkins есть метка с её собственным именем, поэтому поле принимает и конкретную ноду
(`7winds-miha-win`), и выражение меток (`unity && win`, `unity && !mac`). Если под значение не подходит ни одна
нода, сборка падает сразу со списком нод и их меток, а не висит в очереди.

Чтобы выбранная нода оставалась умолчанием для следующих запусков, добавь `NODE_LABEL` в
`options.rememberedParameters`.

Когда нода выделена, имя сборки становится `#<номер> <нода>` (`#19 miha-home`): так агент виден в Stage View и
в списке сборок на странице задачи. Имя, заданное в Jenkinsfile до вызова `unityCi`, не трогается.

# Запоминание выбора в форме запуска

`options.rememberedParameters` перечисляет параметры, чьё значение из последней сборки становится умолчанием
в форме "Собрать с параметрами":

```groovy
options = [
        // ...
        rememberedParameters: ['REMOTE_ICONS'],
]
```

В начале каждой сборки библиотека сравнивает значения этих параметров с умолчаниями задачи и записывает
отличающиеся. Работает и при `SETUP_PARAMETERS=false`: тот управляет набором параметров, а запоминание меняет
только умолчания уже заведённых. Подходит любой тип, который умеет `ParameterDefinition.copyWithDefaultValue`
(boolean, string, text, choice); остальные остаются как были.

Разовые действия (`CLEAR_WORKSPACE_BEFORE`, `RESTORE_LIBRARY_CACHE`, `SAVE_LIBRARY_CACHE`, `SETUP_PARAMETERS_ONLY`)
в список не класть: одна сборка с галкой сделала бы её режимом для всех следующих. `SETUP_PARAMETERS` тоже:
запомненное `false` перестанет заводить новые параметры.
